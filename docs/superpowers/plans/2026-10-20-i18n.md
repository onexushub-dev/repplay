# Internationalization (pt-BR + en-US) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app UI, the voice command, the iOS permission prompts and the watch app work in Brazilian Portuguese and US English, picked from the device language, with English as the fallback.

**Architecture:** A small `src/i18n/` module wraps `i18n-js` with typed TypeScript catalogs (`en.ts` defines the `Messages` type, `pt-BR.ts` must match it), a pure `resolveLocale`, a locale store that React reads through `useT()`, and a plain `t` for non-React code. Formatting helpers in `components/format.ts` use `Intl` with the active locale. Native voice gets the locale through `setVoiceEnabled(enabled, locale)`; permission strings come from Expo `locales` files; the watch gets a String Catalog.

**Tech Stack:** Expo SDK 58, React Native 0.88, TypeScript, `expo-localization`, `i18n-js` (both via `npx expo install`), Jest (jest-expo), Swift (`swift test` in `modules/replay-camera/ios/Core`), SwiftUI String Catalog (`Localizable.xcstrings`).

**Spec:** `docs/superpowers/specs/2026-10-20-i18n-design.md`

## Global Constraints

- Locales: `AppLocale = 'en' | 'pt-BR'`. Default and fallback: `en`. Any `pt-*` device language → `pt-BR`; any `en-*` → `en`; others skipped; nothing supported → `en`.
- No in-app language picker. Language comes from the device (per-app language in system settings).
- Library: `expo-localization` + `i18n-js`, installed with `npx expo install`. Catalogs in TypeScript.
- Interpolation `%{name}`; plurals `{ one, other }` with `count`. Every key has the same placeholders in both languages.
- Catalog areas: `common`, `onboarding`, `setup`, `recording`, `summary`, `games`, `pairing`, `remote`, `clip`, `share`, `modes`, `sources`, `payments`.
- Internal ids (modes, trigger sources) never change; only displayed labels become keys.
- Brand "LANCE" is never translated. English calls recordings "clips"; Portuguese "clipes".
- Voice words: pt-BR `["salvar","gravar"]`, en-US `["save","record"]`; whole-word, case- and diacritic-insensitive; one small constant per locale.
- iOS permission base text is English; `CFBundleAllowMixedLocalizations: true`; `locales` files for `en` and `pt-BR`.
- Do not touch `src/payments/`, payments Tasks 6–8, `ios/`/`android/` generated folders; no device builds.
- Every task ends with `npx jest`, `npx tsc --noEmit` and `npx expo lint <changed files>` green (pre-existing lint errors in `src/app/pairing.tsx`, `src/app/setup.tsx`, `src/app/__tests__/remote.test.tsx` excepted).
- Jest runs in pt-BR (root `__mocks__/expo-localization.ts`), so existing screen tests keep their Portuguese assertions.

## Review Focus

1. **Android language change without restart** — a screen already open must re-render in the new language when the app comes back to the foreground. Test in Task 1: `useT` re-renders after `syncLocale(['en-US'])` is called outside React.
2. **React Compiler memoization** — components memoize on the props they see; a format helper that reads a global locale would keep old text. Components pass `locale` from `useT()` to format helpers; Task 2 tests call each helper with an explicit locale.
3. **English times with ICU's narrow no-break space** (`6:40 PM` uses U+202F in recent ICU) — tests normalize whitespace so they pass on any ICU. Task 2.
4. **Missing key or placeholder typo in one language** — would show `[missing ...]` or a raw `%{x}`. Task 1 parity test compares key sets and placeholder sets of every leaf (and every plural form).
5. **Hard-coded Portuguese left on a screen** — Task 6 guard test fails on any accented character in code (comments stripped) under `src/app` and `src/components` outside tests and an explicit allowlist.

**Interfaces:**
- Produces:
  - `type AppLocale = 'en' | 'pt-BR'`; `resolveLocale(tags: string[]): AppLocale`
  - `type VoiceLocale = 'pt-BR' | 'en-US'`; `voiceLocale(l: AppLocale): VoiceLocale`; `VOICE_WORDS: Record<AppLocale, readonly [string, string]>`
  - `type Messages = typeof en`; `type MessageKey` = dot path to every leaf (a leaf is a string or `{ one: string; other: string }`)
  - `translate(locale: AppLocale, key: MessageKey, params?: Record<string, string | number>): string`
  - `t(key, params?)` = `translate(currentLocale(), …)`; `currentLocale(): AppLocale`; `setLocale(l: AppLocale): void`; `syncLocale(tags?: string[]): void` (default `getLocales().map(l => l.languageTag)`); `subscribeLocale(fn: () => void): () => void`

  - `useLocaleSync(): void` — mounted once in `_layout.tsx`: calls `syncLocale` when `useLocales()` changes and when `AppState` becomes `active`
